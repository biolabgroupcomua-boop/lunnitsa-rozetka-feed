# lunnitsa-rozetka-feed

**Стан: живий.** Фід Розетки для Lunnitsa з фото на білому фоні.

Адреса фіду для Розетки: https://biolabgroupcomua-boop.github.io/lunnitsa-rozetka-feed/rozetka.xml
Стан останнього збору: https://biolabgroupcomua-boop.github.io/lunnitsa-rozetka-feed/status.json

## Як працює
- GitHub Actions щогодини (`.github/workflows/feed.yml`) запускає `build_feed.py`.
- Основа — фід Розетки, який Horoshop генерує щоночі (`lunnitsa.com/marketplace-integration/rozetka-feed/`): категорії, назви, описи.
- З API Horoshop щогодини беруться кількість, наявність, звичайна ціна сайту, назви й описи (name/description російською, name_ua/description_ua українською) і характеристики `<param>`: країна, склад, об'єм або вага, тип шкіри, дія, призначення, EAN. Знижок на Розетку не передаємо (стара ціна прибрана): Розетка дає свої знижки.
- Фото: `site/img`, перелік у `photos.json`. Перше фото кожного товару на білому фоні. Товари без білих фото лишаються з фото сайту (список у `status.json` → `site_photos`).
- Категорії: у фіді лише кінцеві категорії сайту Розетки з `categories.json` (id категорії = `rz_id` = ID з адреси категорії на rozetka.com.ua, напр. …/krem-dlya-litsa/c4657262/), тож Розетка прив'язує їх сама. Категорії Horoshop у фід не йдуть. Новий товар без запису в `categories.json` лишається в категорії Horoshop і видно в `status.json` → `no_category`: дописати його артикул. Після виходу товарів на Розетку id категорій не міняти.
- Вимоги Розетки (sellerhelp.rozetka.com.ua: p185 XML, p217 назва, p212 опис, p210 характеристики, p216 фото) застосовує `rozetka_rules.py`: назва за формулою «Тип Бренд Модель Об'єм (Артикул)» без ком, двокрапок і переліку складу; опис з HTML-розміткою, без «подарунок» і відсилок до карток сайту; `<vendor>` завжди Lunnitsa (бренд у назві); `<article>` = артикул; дата файлу = час збору. Фото менше 400 px у фід не йдуть (`tools/make_photos.py`, MIN_SIDE). `tools/check_feed.py` перевіряє все це перед кожною публікацією: якщо є порушення, фід не публікується.
- Pricecreator Розетки бере назву, опис, бренд і категорію товару лише при першому імпорті: після змін у фіді вже завантажені товари треба видалити й імпортувати заново або правити в кабінеті. Id товарів і категорій не міняти.
- Характеристики: назви й значення Розетки для категорії товару (`rozetka_params.py`): точні назви з кабінету Pricecreator (`pricecreator_params.json`, назви фільтрів на сайті Розетки інші), значення зі списків фільтрів rozetka.com.ua (`rozetka_category_params.json`). Pricecreator зіставляє характеристику лише за точною назвою, і в товарі їх має бути щонайменше 2 (перевіряє `tools/check_feed.py`). Рішення для всіх товарів: «Клас косметики» = Натуральна, «Стать» = Для жінок, парфуми «Нішева».
- Якщо збір не вдався, на Pages лишається попередній фід. Сайт lunnitsa.com і фото на ньому не змінюються.
- Доступ до API — секрети репо `HOROSHOP_LOGIN`, `HOROSHOP_PASSWORD`.

## Оновити фото
Фото беруться з теки дизайнера `OneDrive\DESIGNER\LUNNITSA\Сеты\MakeUp_Lunnitsa`. Після нових фото:
`python tools/make_photos.py` → перевірити `photos_report.md` → закомітити й запушити (`site/img`, `photos.json`). Товар без артикула в назві папки дописати в `FOLDERS` у `tools/make_photos.py`.

## Фото наборів
Білих пакшотів наборів у теці дизайнера немає. Білий фон зроблено в KIE (nano-banana-pro) з першого фото набору на сайті: товари й етикетки не перемальовуються, міняється лише фон (погоджено Olena 19.10). `python tools/make_set_photos.py <артикули>` → `site/img/<арт>_1.jpg` + `photos_sets.json` (після білого фото йдуть решта фото сайту). Скрипт сам звіряє результат з оригіналом і не ставить чужий кадр.

Частина коду сайту лежить у локальному репо `lunnitsa-site` (поля для Розетки: `tools/rozetka_feed.py`).
